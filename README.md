# 舍友大乱斗

[公开在线试玩](https://roomie-rumble-arcade.aa1986884.chatgpt.site) · [运行与测试记录](docs/QA.md)

一款借鉴 90 年代真人数字化街机画风的宿舍格斗页游。支持手机或电脑人机对战、共享键盘或触屏的双人对战，以及两部手机在同一 Wi-Fi 下扫码对战。本项目自带原创角色动作图和夜间宿舍擂台。

## 获取源码

下载仓库中的 `roomie-rumble-v1.4.2-source.zip` 并解压，可获得完整目录源码、测试和构建脚本；也可单独下载 `开始游戏.html` 离线试玩。下文命令在源码包解压目录运行。

## 启动

想自己玩，解压后双击 `开始游戏.html`，或在手机浏览器打开在线试玩版。离线 HTML 自带场景、角色和触控操作。线上试玩页的「好友联机 → 电脑主机开房」入口也可下载主机包。

## 两部手机直接玩

1. 两部手机连上同一个 Wi-Fi，或让一部手机开热点、另一部连入。联网打开[舍友大乱斗](https://roomie-rumble-arcade.aa1986884.chatgpt.site/?play=phone)，建议用系统浏览器。在线试玩站现已公开，持有链接即可访问。
2. 第一部手机点「好友联机 → 在线开房」，选好要带上场的角色，再点「创建房间」。让舍友用第二部手机扫码，也可以发邀请链接；如果已经打开游戏，直接在「好友联机 → 在线开房」里填写六位房号。
3. 对方选好自己的角色，点「加入房间」。两边都显示就位后，房主点「开始对战」。手机横屏后，左手八向走位，右手普攻、双技能、奥义和替身。

建房和加入需要能打开在线游戏。第一部手机计算对战，优先与另一部手机直连。校园网或访客 Wi-Fi 如果隔离设备，游戏会自动通过房间服务转发角色和操作；转发时要持续联网，按键响应取决于网络。双方应保持游戏页打开，房主刷新页面会丢失当前一局。

## 用电脑做局域网主机

1. 在一台装有 **Node.js 18 或更新版本**的电脑上解压整个主机包。Windows 双击 **启动局域网.cmd**；macOS 和 Linux 可在解压目录运行 `node server.cjs`。保持启动窗口开启。默认端口为 4399，占用时可运行 `node server.cjs --port 4400`。
2. 在启动器打开的页面点击「好友联机 → 电脑主机开房」，选择自己要用的角色，点击「创建房间」。电脑想做专用主机时，也可直接用第一部手机打开启动窗口中显示的 Wi-Fi 地址来建房。
3. 让另一台设备连上同一 Wi-Fi，扫描房间二维码，或直接打开邀请链接。对方选好自己的角色、点「加入房间」，房主即可点「开始对战」。手填六位房号时，两台设备都要先打开同一台主机提供的游戏网址。
4. 每个设备只控制自己的选手。手机左右拇指可同时斜向走位和出招；横屏时擂台与触控按键同屏。电脑上的两端均可使用 J / K / L / I / U。房主可以在结算后开下一场。
5. 手机切到后台或断线，服务器暂停对局并保留座位约两分钟。在原浏览器标签页返回可以续局。房主主动离房会关房。

若手机打不开链接，核对两台设备的 Wi-Fi 和电脑启动窗口显示的地址。电脑有多个网卡时，可在房间页切换「主机网络地址」再扫码。若系统弹出防火墙提示，为本次对战允许 Node.js 访问专用网络。校园网或访客网络可能隔离设备，也可以让双方接入同一手机热点。

## 做一个自己的角色：两条真实 AI 路径

1. 在「角色工坊」选一技能或二技能。输入好友描述，例如「爱打羽毛球，总把拖鞋当球拍」。点击「AI 帮我想技能描述」，生成可编辑的创意描述；也可以跳过这一步，直接手写技能描述。
2. 确认技能描述后，点击「AI 生成可用技能」。第二阶段产出 `kind / delay / cooldown / power` 等实际参数，不仅改一个招名。支持突进、飞行道具、护盾、近身震荡、回复五种机制。
3. **没有 Key：**点击任一 AI 按钮会展开对应步骤的提示词，不会自动调用模型。复制到已有 AI 聊天账号，粘贴完整 JSON，点击「应用这一步的 AI 结果」。第一步需要 `description` 字段；第二步需要有效的 `name、prompt、kind、delay、cooldown、power`。AI 聊天是否收费或限额由相应服务决定。
4. **可选 API 直连：**在下方设置 HTTPS 兼容接口、模型和 Key，再点击对应 AI 按钮。带头像时需要图文模型和浏览器跨域支持。Key 仅在当前页内存；描述与头像会发到所填服务，可能产生该服务的费用。当前未用真实模型 Key 完成端到端联测。
5. 第一阶段只更新描述，不自动装配，也不偷偷用规则替代 AI。无效或超范围 JSON 会报错并保留原技能。只有第二阶段的合法结果才会装入相应技能槽。描述改动后，要先生成/导入新技能，才能试招或保存。
6. 点击「进入训练场试招」，观察飞行道具、回复、冷却和实际命中，再返回修改和保存。若只需离线试玩，可明确展开「不用 AI：本地规则预览」，选择非 AI 编排。
7. 可上传本人或获同意的照片，调整裁剪位置，选择两套二维动作底模。照片在浏览器本地合成到动作帧，并非生成完整三维人物。

## 操作

手机左手拖摇杆前后、左右走位，右手点普攻、一技能、二技能、奥义或替身。移动和出招可以同时操作。电脑键位如下。

| 动作 | 1P | 2P（小键盘） | 2P（无小键盘） |
| --- | --- | --- | --- |
| 上下左右走位 | W / S / A / D | ↑ / ↓ / ← / → | ↑ / ↓ / ← / → |
| 普通攻击 | J | 小键盘 1 | 顶部 7 |
| 一技能 | K | 小键盘 2 | 顶部 8 |
| 二技能 | L | 小键盘 3 | 顶部 9 |
| 奥义 | I | 小键盘 5 | 顶部 0 |
| 替身 | U | 小键盘 4 | 顶部 6 |

靠近对手，和他站在同一条线上，连续点普攻可以打出三段。两招各自冷却。普通对局初始有两点奥义点，技能有效命中可以攒点；满四点可放奥义，替身不是召唤：受击后约半秒内按，或提前按住等受击，花一点绕到对手背后，冷却 12 秒。成功后需松开再按。界面会显示冷却、缺能量或待受击状态。打空不会涨点。体力归零后先展示倒地与 K.O.，约 1.5 秒后再显示结算；期间不再受伤或推进对局计时。60 秒内先把对方体力打到零者获胜，超时比较剩余体力。

训练场不限时且开场满能量，可先试奥义。点击「假人反击」练习受击时的替身时机。在大厅用 A / D 或 ← / → 选择本地模式，按 J 开战；本机对战按 Esc 或点击「暂停」可暂停。

## 实现

- `dist/design.js` 配合 `dist/kit.js` 负责双技能编排、图文模型调用、生成提示词与 AI 方案导入。所有技能输入都会受数值和机制范围约束。
- `dist/art.js` 负责数字化角色动作、逐帧人脸定位、服装配色和场景渲染。当前有两套二维身体底模，每套五帧姿势。
- `dist/combat.js` 在固定时间步里处理双人输入、电脑对手、防守、命中、位移、冷却和胜负。电脑对手使用本地游戏逻辑。
- 局域网模式由 `server.cjs` 统一计算双方的位置、伤害、冷却和结算，`dist/lan.js` 发送按键并接收画面状态。主机没有第三方运行依赖。
- 手机直连模式由 `worker/pair.mjs` 配对，`dist/phone-link.js` 建立 WebRTC 数据通道，`dist/peer.js` 在房主手机运行对战。房间服务保存临时配对信息。直连时，角色和按键经设备间的数据通道传输；切换转发时，服务临时传输裁好的角色头像、操作和战况，显式离房时删除该房间的数据。
- 开发者可用 Node.js 22.13 或更高版本运行 `npm run dev` 启动手机房间的本地预览。运行 `python3 package-release.py` 重建下载包，再运行 `npm run build` 生成可部署的 Worker。数据库迁移位于 `drizzle/`，部署时绑定名为 `DB` 的 D1 数据库。
- 角色草稿存于本机浏览器。入房时会将选手名称、头像、外观与技能同步给房间主机和对手，原始上传照片和人物故事不进入联机消息。点击「用 AI 设计」直连时，头像与描述发给指定模型接口；Key 保留在当前页面内存。

## 笔试验收与已知边界

建议评审先解压后双击 `开始游戏.html`，无需登录、安装依赖或 API Key。在线试玩目前仅账号所有者可访问，未获授权的评审请用下载包。完整局域网联机用 Node.js 18+；手机配对服务的本地开发和完整自动测试需要 Node.js 22.13+。

本项目使用 AI 辅助开发和美术制作。游戏电脑对手是规则驱动的 CPU，不是运行时大模型。角色照片是本地裁剪后合成到两套二维动作底模，不是照片生成完整 3D 人物。无 Key 时，可将提示词交给已有 AI 聊天会员，再导入返回的 JSON。直连外部模型需要自备 API Key、图文兼容能力和 CORS 支持；当前没有真实付费模型接口的端到端验收记录。

文字招式最终只能映射为五种已有机制，不能生成任意代码。`power` 是机制强度，不总等于扣血或回血：回复为 `round(power × 0.72)`，护盾持续时间为 `0.72 + power × 0.045` 秒，技能实际起手还包含固定 0.095 秒动画准备。描述中超出引擎能力的部分不会生效。回复有效恢复体力、护盾成功挡招也可以增加奥义点。

照片请使用本人、获同意的朋友或虚构角色。不要将未经同意的真实人物用于羞辱、冒充或公开传播。默认只在本地处理照片；加入房间将发送裁好的头像及公开技能给对手，点击外部 AI 设计会发送头像与人物描述到指定模型服务。

运行 `npm test` 可复现回归测试（Node.js 22.13+，零第三方依赖）。本次 34 项检查覆盖数值与 JSON 边界、确定性战斗、冷却/奥义/替身、房间权限、双端状态一致、断线重连和转发协议。浏览器验证不等于实体手机验收；iOS/Android 真机多点触控、校园网设备隔离和不同网络的延迟尚待实际体验。

## v1.3.2 联机入口

大厅现在统一为「好友联机」。进入后选择「在线开房」（无需电脑主机，需联网及网站访问权限）或「电脑主机开房」（一台电脑运行 Node.js，其他设备同局域网加入）。两种方式都支持手机和电脑；它们仍使用原来的不同底层连接方式。建房前可以切换，入房后必须先离房，避免丢失座位。旧邀请链接仍直接进入对应房间流程。

## v1.4.0 工坊更新

两阶段 AI 工作流已加入；描述到技能的无效输出不再自动默认处理。API 响应使用模拟数据验证，浏览器实测导入 projectile 后训练假人100→86血，导入 heal 后自身70→84血。它们验证装配和执行，不代表站内已接通免费实时模型。

## 从源码复现

```bash
# Node.js 18+：本地游戏和局域网主机
node server.cjs

# Node.js 22.13+：完整自动测试
npm test

# Python 3 + Node.js：生成离线页面、主机下载包，再构建在线 Worker
python3 package-release.py
npm run build
```

在线房间后端需要配置 D1 数据库；仅把静态文件部署到 GitHub Pages 不会提供在线开房服务。本仓库未包含模型密钥、用户上传头像或运行期房间数据。
